默认展开最新版本，点标题行展开或收起。

设置页重新分四类

  • 设置页改成 基础 / 下载 / 风格 / 其他 四个标签，按用途归类（不再有「个性化 / 启动 / 其它」三个独立页面）：
    • 基础：界面语言、更新方式、关闭窗口时、本地目录、游戏资源清理、本机内存、启动选项、内存分配、高级选项、启动失败诊断；
    • 下载：下载源、下载、社区资源、辅助功能、版本与自动切换、CurseForge、模组与 Java；
    • 风格：标题栏、界面图标、离线皮肤、主题配色、背景（含壁纸引擎目录与壁纸列表）；
    • 其他：背景音乐、启动音效、每日一言接口。
  • 删掉设置页里那块「关于 / 打开关于页」（关于页本身还在侧栏）。

移除 FastMinecraftMirror 下载源

  • 下载源只剩 官方 / BMCLAPI / 上海交大 / 自动测速；老配置里存过它的会自动回落成「自动」。

目录结构调整（升级后首次启动自动迁移）

  • 启动器数据（配置、日志、皮肤、披风、JDK、下载缓存、更新包）从 <根目录>\NaiWa 搬到 <根目录>\main\NaiWa（安装版）；便携版仍在程序目录下的 NaiWa。
  • 服务端目录从 <根目录>\servers 搬到 <根目录>\.minecraft\servers。
  • 迁移是自动的：先记录标记，逐个目录搬（同盘瞬时改名，跨盘复制并校验大小后再删源），目标已有同名文件时不覆盖、把旧文件改名成 *.migrated-<时间> 保留；任何一步失败都保留原数据并继续用旧位置，下次启动重试。
  • DL（GitHub / 自定义下载目录）不搬，仍在 <根目录>\DL。

链接与致谢新增三个启动器

  • 新增 HMCL / Luna Launcher / QooKix，致谢共 29 项（同类启动器排在一起，仍不分组显示标题）。

安装包体积优化（方便蓝奏云上传）

  • 免安装版新增 .7z 包（75 MB），比原来的 .zip（118 MB）小很多，蓝奏云免费账号（单文件 100 MB 上限）可以直接传；.zip 仍保留给 GitHub Releases。
  • 安装版 89 MB、单文件版 76.5 MB，都在 100 MB 以内。

关于页：链接与致谢新增「官方网站」

  • 新增条目「官方网站」（下载与更新日志），指向 https://jijiguowang123.github.io/naiwai/，排在致谢最前面；致谢共 26 项。

实例目录改成和 PCL2 一样的布局

  • 一个实例 = .minecraft\versions\<实例名>\ 一个目录，里面同时有版本文件与游戏资源：<实例名>.json（完整版本描述）、<实例名>.jar（client jar，硬链接优先，省空间）、natives\、mods\、config\、saves\ 等，启动器自己的记录放在 naiwa\instance.json。
  • 不再是「资源在 instances\、版本在 versions\<版本号>\」两处分开；assets、libraries 继续共享。
  • 建实例后会清掉不再需要的共享原版目录（versions\1.21.4 之类），不留残留；还有老实例依赖它时会保留。
  • 删实例删干净：整个实例目录连同 json/jar/记录一起删掉，不影响其它实例。

老实例迁移：新增按钮（不自动搬）

  • 实例页顶部新增「迁移旧版本布局」：检测到旧实例才可用，弹窗列出「旧路径 → 新路径」；执行顺序是复制 → 逐文件校验 → 原子改名 → 改记录 → 删源，失败保留原文件、游戏运行时拒绝、可续做、重复点幂等。
  • 不点迁移的老实例仍然按旧布局正常启动，不会偷偷搬文件。

设置：清理所有游戏资源文件

  • 设置 → 其它 新增「游戏资源清理」：先显示 libraries / assets 的占用（可勾选额外清理无人使用的原版版本目录），必须勾选确认才能清理；明确提示「删除后需要重新下载，可能几百 MB 到 1 GB 以上，需要联网」。
  • 白名单守卫：只允许清 libraries、assets 与没人用的原版版本目录；instances/实例目录、NaiWa 配置、servers、skins、DL 一律不碰，.. 穿越与符号链接会被拒绝。

清理后启动会自己补回来

  • 启动前先快速检查依赖：缺 libraries 或 assets 时自动按需下载补齐（进度显示在「管理」页的「补齐游戏依赖」），补完继续启动；离线或镜像不可用时给可读原因并中止，不再让你撞「启动失败」。
  • 依赖齐全时只多一遍 stat（实测约 1 ms），零网络请求。

整合包安装也用新布局

  • 在线整合包与本地整合包压缩包安装后同样是「一个实例一个 versions\<实例名>\」，不再出现一个实例两处住的情况。

侧栏整理：设置合并、页面精简

  • 「个性化」「启动」「其它」三个页面并入「设置」，设置页顶部用标签切换（通用 / 个性化 / 启动 / 其它）；侧栏只留一个「设置」，并把它放到最下面。
  • 移除侧栏的「游戏」页（原版版本列表），装原版去「实例 → 新建」里选版本即可。
  • 图标跟着换：首页用房子、管理用下载图标、设置用推子图标。
  • 「GitHub 加速下载」整块搬到娱乐页。

资源：插件有了加载器与类别筛选

  • 插件类型下侧栏新增：加载器下拉（全部 / Paper / Spigot / Bukkit / Folia / Purpur / Sponge）与插件类别列表（19 项可多选）。选中即进搜索，切回其它类型时自动恢复原筛选项。
  • 所有资源的类别名改成随界面语言显示：中文界面显示「优化 / 库 / 装饰 / 世界生成…」，切英文、日文时同步变；详情页的类别标签也算在内。未收录的类别会显示原名（当前真实来源 154 条已全收录）。

资源：没选实例时安装按钮也会判断能不能装

  • 详情页没选安装目标时，版本行的安装按钮直接置灰禁用并写明原因（「先选一个实例再安装」/「先选一个服务端再安装」），不再点了才提示；选中原版实例、插件服装模组等不可装的情形同样置灰，切换目标即时更新。

新增下载源：FastMinecraftMirror

  • 设置/首页的下载源里新增 FastMinecraftMirror（fastmcmirror.org），按它官网公布的映射替换官方下载地址（launchermeta / launcher / resources / libraries / forge maven / fabric meta & maven / liteloader / OptiFine）；「自动」模式会在 BMCLAPI 与它之间取更快的，失败自动回退官方。
  • 说明：这个源的连通性没能验证（我这边解析到被劫持的 IP、证书不匹配），实际可不可用要你在自己网络里试；它覆盖的范围也比 BMCLAPI 窄（piston-meta 等不在其映射表内，仍走官方）。

关于页：链接与致谢新增五个启动器，同类相邻排序

  • 新增 樱梨启动器 EririLily / KLP Launcher / GPCL / Allay / AML（AML 用字母图标），共 25 项；不分组、不显示小标题，只把同类排在一起（本项目 → 官方与内容站 → 镜像与加速 → 联机与工具 → 同类启动器）。

首页：最近游玩改翻页

  • 「最近游玩」不再横向滚动，改成和「资源」页同一套翻页控件：每页 10 个，固定排成两行 × 五列——窗口拉窄时卡片会变窄，但仍然是「每行五个、共两行」，不会折成 4+3；翻页不会改变当前选中的实例。

首页：实时启动日志

  • 首页下方新增「启动日志」面板：点「开始游戏」后实时显示这个实例的启动输出（游戏 stdout/stderr 与启动器自己的记录），最多保留最近 200 行，自动跟着滚到底。
  • 面板顶部能看到状态（未启动 / 正在启动 / 运行中 / 已退出 code），可以「清空」、可以关掉「跟随」自己往回翻；切换实例时会自动切到该实例的日志，不会串台。
  • 主进程按批次合并后再推给界面（约 150ms 一批、单批最多 200 行），不会因为日志刷得太快拖慢界面。

新增「首页」

  • 启动器现在默认落在首页（侧栏第一项）：大卡片显示当前选中的实例（名称 / Minecraft 版本 / 加载器与版本），右侧就是「开始游戏」。
  • 最近游玩横向卡片列出最近用过的实例，点一下就切换选中并可以直接启动；没有游玩记录的会标「还没玩过」。
  • 三张统计卡：启动用时（当前版本还没埋点，显示 —，后续补）、内存（本机可用 / 总计 + 该实例分配给多少）、下载源（当前源与说明，例如「自动测速，镜像优先」）。
  • 首次启动会自动选中最近玩过的实例（没有记录就选第一个）；如果你曾显式选「不选择实例（仅浏览）」，会保持不选。

启动按钮统一到首页

  • 实例页的卡片不再有「启动」按钮（其余按钮都在），启动统一在首页完成；首页选中的实例与「资源」页的安装目标是同一份状态，切换后自动同步。

更新：显示下载进度，静默覆盖

  • 关于页「检查更新」旁边会显示下载进度（百分比 + 已下载/总大小 + 进度条），状态依次是：正在检查 → 正在下载 vX → 下载完成准备安装 → 正在安装并重启；手动点「立即更新」也一样有进度。
  • 安装过程中不再弹黑框：安装包里的权限修复（icacls）改成隐藏窗口执行，全程静默覆盖旧版本并自动重启。

启动失败诊断：AI 分析 + 在线分析入口

  • 内置规则诊断不变（默认就用它）。想更细的分析，可以在「启动」页填一个 DeepSeek API Key：填了才会把本次崩溃日志的末尾（最多 200 行 / 12k 字符）发过去让 AI 给结论、可能原因、修复建议和可疑模组。
  • AI 失败、超时、没填 Key 一律静默回退到内置诊断，不会打断启动流程；Key 不会写进日志、也不会进导出诊断包。AI 结论在弹窗与 diagnosis.txt 里都标注「仅供参考」。
  • 诊断弹窗新增「在线分析崩溃报告」按钮，一键把崩溃报告送到 MCToolbox 的分析页（按界面语言给对应语言版本），旁边注明会上传到第三方站点。

原版实例不再显示模组/光影

  • 原版（Vanilla）实例的「内容」面板只保留资源包，模组与光影包标签整块不出现；「资源目录」入口也不会再打开不存在的 mods/shaderpacks。

服务端也有插件/模组管理

  • 开服页每个服务端新增「插件」或「模组」入口（按核心决定：Paper/Purpur/Folia 是插件、Fabric/Forge/NeoForge 是模组、Arclight 两者都有、Vanilla 禁用并说明原因）。
  • 面板里能看数量、搜索、刷新、打开目录，并对每一项启用/停用（改名为 *.jar.disabled，重启服务端生效）、更新（按文件 sha1 反查来源取新版，成功才替换旧文件）、删除。

实例内容也能启用/停用

  • 实例的模组/光影/资源包列表新增「启用 / 停用」（同样用 .disabled 后缀，加载器不会加载），停用的项灰显并标「已停用」；删除与更新照旧可用。

内存：上限就是本机物理内存 + 一键清理

  • 实例与开服的内存上限都改成「本机物理内存」（不再是写死的上限），滑杆旁显示「本机共 X GB」，超限保存会被夹到上限并提示。
  • 启动页新增内存占用条（每 2 秒刷新，页面不可见时停），以及「清理运行内存」按钮：把本启动器自己（含子进程）的工作集还给系统，并显示释放了多少。
  • 诚实说明：这只是把页面挪进备用列表，可用内存会上升但下次访问要回填，效果看当时情况，不是魔法；只动自己，不碰其它程序。

背景个性化：去掉预览图与路径

  • 本地图片/视频、随机图 API、Steam 壁纸引擎三个来源都不再显示预览图和文件路径/URL，界面更紧凑；开关、来源切换、播放方式、轮播间隔、音量、保存与刷新等控件全部保留。

娱乐页：下载自定义文件

  • 新增「下载自定义文件」卡片：填地址、选保存目录（默认 <启动器根目录>\DL）、可选自定义文件名，点一下下载；进度显示在「管理」页，可取消/续传，完成后可一键打开所在文件夹。
  • 地址非法、非 http(s)、文件名含非法字符都会给可读提示；文件名留空时按 URL 末段推断，推断不出用 download-<时间戳>.bin。

设置页：移除旧开关

  • 删掉「关闭到托盘（旧开关）」整块（现行机制是「关闭窗口时」三选项：询问我 / 隐藏到托盘 / 直接退出）。

链接与致谢新增两项

  • 新增 FastMirror（服务端核心镜像）与 Prism Launcher（同类启动器），致谢共 20 项。

侧栏：连接状态与版本号始终可见

  • 窗口被拉矮时，左侧导航项自己滚动（和右侧内容一样），底部的「已连接主进程」与版本号固定在可见区，不再被挤出窗口。
  • 顺带把导航与底栏的间距收紧了一点，滚动条做成细条，不会压到导航文字。

CurseForge 不用填 Key 了

  • 接入社区镜像（MCIM，mod.mcimirror.top 的 CurseForge 兼容接口）：不填 API Key 也能搜索、看详情、列文件、下载；填了 Key 仍然走官方接口。
  • 实测：无 Key 搜 jei 能出 JEI（6.39 亿下载）、详情正文 2328 字、文件列表带大小与 sha1、走镜像给的直链真下载一个 715 KB 的 jar 并校验 sha1 一致。
  • 镜像不可用（5xx/429/超时）时给「社区镜像暂时不可用，请稍后重试」，不再误导你去填 Key。

新增「娱乐」页（在设置后面）

  • 每日人品：点一下抽取今日人品（1–100），按日期固定——同一天点多次都是同一个数，第二天自动刷新；100 个数值各有不同反馈。
  • 每日一言：点卡片随机抽一句；默认走内置接口（uapis.cn/api/v1/saying），可以在设置里换成自己的 API（自动从 JSON 里取文字字段，取不到就显示原文）。

资源：整合包直接建新实例

  • 整合包不再需要选安装目标，点一下就安装并新建实例；侧栏「安装目标」在整合包类型下会置灰并说明原因。

关于页：板块重排 + 致谢新增五个启动器

  • 顺序调整为：最新新闻 → 功能简介 → 更新日志 → 核心团队 → 链接与致谢。
  • 链接与致谢新增 MoLaunch / XMCL / AxlMC / Oaoi / Bakaxl 五个同类启动器（各用其站点图标），致谢共 18 项。
  • 去掉 Steamcommunity 302 卡片上的「推荐：」前缀。

皮肤页：正版账号只显示官方面板

  • 选中微软正版账号后，页面只保留「微软正版皮肤 + 披风」这一个面板：顶部的「应用到实例」栏、本地皮肤库（3D 预览 / 已保存 / 内置皮肤）、底部的本地披风库、以及最下面的推荐素材站栏（LittleSkin / mcstat）全部不显示。
  • 这些都是整块不渲染（不是 CSS 隐藏），相关查询也一并停掉；切回离线账号后全部恢复。正版账号下拖入 PNG 不会再偷偷导入到看不见的本地库，只提示「本地皮肤库请切到离线账号使用」。

披风：去掉「移除披风」按钮

  • 正版披风面板只保留「刷新披风列表」与「应用」，不再提供「移除披风」（接口仍在，只是不给入口）。

资源：原版不能装模组/光影、可以挑版本、能回原页面

  • 原版实例不能装模组与光影：安装目标弹窗里原版实例项置灰并说明原因；侧栏选中原版实例时，模组/光影的安装按钮也会禁用并给出原因（整合包、资源包、插件不受影响）。
  • 装到实例时可以先挑版本：目标选好后会列出该实例 MC 版本 + 加载器可用的文件（文件名 / 版本 / 更新时间 / 下载量），点哪个装哪个；列表为空或查询失败会退回「自动挑最新」并提示。
  • 详情页新增「原始页面」按钮（在 MCMOD 搜索左边），一键打开该模组在 Modrinth / CurseForge 的原始页面。

正版皮肤：只能显示，官方优先

  • 皮肤页的「微软正版皮肤」改为只读：移除了上传 PNG、用 URL 设置、经典/纤细选择等所有修改入口，只显示当前正在使用的皮肤，并给一个「去微软官网修改皮肤/披风」的按钮——打开的是官网的皮肤与披风页面（按界面语言选 zh-hans / en-us / ja-jp）。
  • 官方皮肤优先：用正版账号启动时，启动器不再注入本地皮肤/披风，避免 CustomSkinLoader 那套把官方皮肤盖掉（日志会写「正版账号：优先使用官方皮肤，已跳过本地皮肤注入」）。离线账号行为不变，本地皮肤库照旧可用。

披风：只显示名字

  • 去掉了披风缩略图（不再加载披风图片），列表里只显示你拥有的披风名字，当前使用中的带标记。
  • 「刷新披风列表」「应用」「移除披风」都保留，应用按钮改小。

启动失败现在会自己说清原因

  • 游戏异常退出后，启动器会读这次启动日志的尾部并自动诊断，把结论写进日志（# 诊断： / # 建议：），同时弹窗告诉你。
  • 能识别六类原因：显卡驱动崩溃（帧里出现 atio6axx.dll / nvoglv64.dll / ig*icd64.dll 之类）、Java 不信任证书（PKIX path building failed，常见于 Steamcommunity302 这类 HTTPS 代理）、Java 版本不对（UnsupportedClassVersionError）、内存不足、JVM 参数导致起不来、模组冲突/缺前置。
  • 日志按 UTF-8 / GBK 双解码，中文日志不会因为编码变成乱码而漏判。

修复：关闭软件后重新下载不再从头开始

  • 根因有三个，都修了：

1. 带哈希校验的下载在「sha1 对不上」时会把半成品和续传记录一起删掉——而半成品本来就不可能对上完整文件的 sha1，于是每次重启都从 0 开始。现在只要存在续传记录就不当作坏文件，交给续传继续。

2. 续传记录是直接写文件，进程在写盘途中被结束时留下半截 JSON、下次读不出来；而且 1 秒才落一次盘（快网络 1 秒几十 MB）。现在改成原子写（临时文件 + 改名），并按「每 250ms 或每 2MB」落一次。

3. 点「继续」时进度会被重置成 0，看起来像从头下。现在不清零，重启后显示真实进度。

  • 实测（两阶段，阶段 1 在约 30% 时直接结束进程）：
    • 本地 64MB 夹具：第二阶段只需再传 78.0% 的字节，最终大小与 sha1 均正确；
    • 真实 CDN（清华 TUNA 的 JDK 21 包，195MB）：第二阶段只需再传 71.0%，最终大小一致。
  • 任务的已下载字节 / 总大小 / 速度会随记录持久化，重启后在「管理」页就能看到上次的进度。

杀毒软件误报

  • 默认关闭两处敏感行为，设置里可显式开启：
    • 「高级进程操作」：以前每次启动都会旁挂一个隐藏的 PowerShell 脚本，等游戏进程出现后设置优先级、修改窗口标题——这类「操作别的进程」是杀软的重点特征。现在默认不执行，只有用户主动开启才走这条路。
    • 「离线本地皮肤 API」：给离线账号注入 authlib-injector（javaagent）来读本地皮肤/披风，注入同样敏感。默认关闭，需要时再开；关着时用「一键安装 CustomSkinLoader」的方式。
  • 第三方（Yggdrasil）账号登录仍然需要 authlib-injector 注入，这一条无法关闭（否则第三方账号无法登录），已在说明里如实标注。
  • 新增 docs/AV-FALSE-POSITIVE.md：列出程序会做与不会做的全部行为、构建设置（不加壳、不混淆，asar: false 明文分发）、exe 版本信息字段，以及 Defender / 360 / 火绒的误报申诉入口与说明要点。README 增加对应小节。
  • 说明：单文件便携版是 7-Zip 自解压结构，天然更容易被启发式误判；遇到误报建议改用 Setup 安装版或 portable-x64.zip。

  • 「关闭到托盘」这个设置项以前点了没有任何作用（代码里只有开关、没有托盘实现）。现在真正生效：开启后点窗口关闭不再退出程序，而是隐藏到系统托盘；右下角出现一个小图标，单击/双击或右键菜单「打开界面」都能把窗口叫回来，右键「退出启动器」才是真正退出（会先停掉正在运行的服务端）。
